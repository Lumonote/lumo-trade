# 项目问题总结（只读核查发现）

> 本文仅记录核查发现的问题与影响，**不修改项目代码**。问题按严重程度排列，供后续改进参考。

## 1. 数据格式与口径不一致（影响数据可直接复用性）

1. **日期存储格式不统一**
   - `moneyflow_dc`：965,398 行 ISO（`2025-11-05`）+ 157 行紧凑（`20260529`）混在同一列；
   - `daily_basic / market_daily / trade_calendar`：紧凑 `YYYYMMDD`；
   - `ohlcv.ts`：`YYYY-MM-DD HH:MM:SS`。
   - 影响：跨表按日期 JOIN 或等值查询时，若不兼容两种格式会漏数据；对日期列直接套函数比较又会导致全表扫描。

2. **个股代码口径不统一**
   - `ohlcv / hsgt_individual`：裸 6 位；
   - `daily_basic / moneyflow_dc / dragon_tiger_inst`：带后缀 `XXXXXX.SH/SZ`；
   - `top10_floatholders / stk_holdernumber`：两种形式混用。
   - 影响：同一只个股在不同表无法直接用等值连接，需统一归一化。

## 2. 数据覆盖不完整（影响“全市场”结论）

1. **`market_daily` 只有指数行**：每个交易日仅 2–4 行（上证/沪深300/中证1000/国证2000），并非全市场个股日线。若直接展示，容易被误当成全市场。
2. **`ohlcv` 仅覆盖约 202 只个股**：只有被单独分析过的个股才有前复权日K，非全市场。
3. **`trade_calendar` 只含交易日（is_open=1）**：不含周末/节假日，无法据“未命中”区分“休市”与“日历未覆盖”。
4. **`daily_basic` 仅 30 个交易日**（2025-12-26 ~ 2026-02-09），估值快照时间窗很短。

## 3. 数据过期与同步失败

1. **沪深港通 `hsgt_individual` 严重过期**：最新仅到 2024-08-16，不能用于当前北向判断。
2. **同步日志显示批量失败**：cyq 失败 169、lhb 失败 45、jgdy 失败 14，说明部分来源在 2026-06 初的同步不稳定。
3. 多数表最新日期停在 2026-06 ~ 2026-08，相对 2026-10-29 存在明显滞后。

## 4. 大量功能表为空

财报、机会发现、热门板块、模拟盘、量化雷达、板块序列、市场资金流、个股新闻、星轨等表为 0 行。这些功能在应用侧可能已实现，但本地库尚未产生数据；需要在 UI/文档中明确“暂无数据”，避免空表被误读为功能缺失或被伪造。

## 5. 运行环境的潜在坑

- 本机默认 `python3` 为 3.14，且**没有** pandas/requests/akshare/tushare；依赖齐全的是 `/usr/local/bin/python3.11`。
- 若脚本默认用 `python3` 运行并依赖第三方库，会直接 ImportError。建议核心数据能力尽量不依赖第三方库，或在文档中明确解释器路径。

## 6. 合规相关提示

- 项目现有 `skills/investment-opportunity-discovery` 含评分、评级、目标价、买卖信号等内容，属于“荐股型”表述。对外提供时需注意：
  - 明确标注为研究/模拟用途，不构成投资建议；
  - 数据查询与“荐股/决策”应分离；
  - 避免承诺收益、避免把历史回测结果表述为未来收益保证。
- 本技能包已严格规避上述表述，仅做事实查询。

## 7. 建议的改进方向（不代为实施）

1. 统一日期与代码口径（写入时归一化，或提供统一视图）；
2. 补齐全市场个股日线与完整交易日历（含休市标记）；
3. 对过期数据与空表在应用层统一打“数据时点/暂无数据”标签；
4. 同步失败增加重试与告警，并在来源诊断中暴露；
5. 明确各功能所需解释器与依赖，降低环境不一致带来的问题。
