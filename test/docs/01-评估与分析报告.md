# Kronos 数据查询技能包 — 评估与分析报告

> 范围：基于项目现有接口与数据结构，评估“按日期查询、适合研究复核”的能力边界，并给出只读、不荐股的技能包设计。本报告**不修改项目原有代码**，所有结论均来自对本地库的只读核查。

## 1. 评估目标与约束

用户要求把数据相关功能以**渐进式披露**组织为多个可发现 Skill，每个 Skill 含多个功能点，且满足：

- **只做查询、不做荐股**，不违反证券相关法规；
- 支持请求**某个日期**的技能包数据，得到适合研究复核的结果；
- 对缺失、过期、不可用数据保留原状态与可取得时间，**不把历史快照表述为实时行情**；
- 查询参数或数据源不支持指定日期时，明确说明限制，**不自行构造当日结果**；
- 交付可发现 Skill、运行入口、依赖说明，以及可复现验证；
- 不读密钥到日志，不删除/重置用户数据。

## 2. 项目数据层现状

### 2.1 服务与入口

- 真正后端：`webui/robyn_app.py`（Robyn，约 90+ 路由）；
- `lumo_app.py`：CLI 菜单；
- `market_server.py`：8000 端口星系可视化服务，实时来自腾讯 `qt.gtimg.cn`；
- 数据访问集中在 `data_store/`：`connection.py`（SQLite，WAL + 5s busy timeout）、`schema.py`（版本化迁移，当前 v21）、各 `*_repo.py`（pandas 读写）。

### 2.2 主库

- 主库：`data/lumo_data.sqlite`（约 724MB，schema v21）；另有 `data/pattern_fingerprints.db`。
- 路径可由 `KRONOS_SQLITE_PATH` / `KRONOS_DATA_DIR` 覆盖。

## 3. 合规边界

技能包严格限定为**数据查询与事实呈现**：

- **不输出**：买卖建议、目标价、止损/止盈、评级（A/B/C）、评分、盈利预测、荐股结论；
- 按 `net_amount` 等字段的排序，明确标注为**事实排序**，不是推荐或买入信号；
- 历史快照统一 `data_nature=historical_snapshot`，绝不表述为实时；
- 项目现有 `skills/investment-opportunity-discovery` 含推荐/目标价/买卖信号，新技能明确规避该风格。

## 4. 时效与缺失处理原则

1. **历史快照 ≠ 实时**：每条结果带 `data_nature` 与 `as_of`（实际数据日期）。
2. **缺失即缺失**：空表/区间外返回 `no_data`，不构造当日结果；同时给出最近可参考日期（双向查找）。
3. **过期即标注**：如沪深港通最新仅到 2024-08-16，明确标注“已过期，不能表述为当前值”。
4. **不支持日期就说明限制**：如 `trade_calendar` 只含交易日，未命中日期不武断判定为休市，返回 `limited`。
5. **实时不在范围**：实时行情由运行中的应用/自选服务提供，不在日期查询技能内。

## 5. 技能设计（渐进式披露）

- **第一层（发现）**：`test/skills/README.md` + 机器可读 `skills.manifest.json` + 每个 `run.py list`。
- **第二层（技能入口）**：每个技能的 `SKILL.md`，说明用途、何时用、功能点、入口、限制。
- **第三层（深入）**：每个技能的 `references/data-model.md`，含表结构、口径与取数方式。
- 共 **6 个技能 × 4 个功能点 = 24 个功能点**。

## 6. 运行时与可移植性

- 核心只读查询**仅用 Python 标准库 sqlite3**，任何 CPython 3.9+ 可运行；
- 以 `file:<path>?mode=ro` 物理只读打开，**无法写入/迁移/重置**；
- 不依赖 pandas/requests/akshare/tushare（这些仅应用侧联网更新使用）。

## 7. 结论

- 项目本地库已具备按日期查询的**历史快照**能力，但覆盖不完整、口径不统一、部分数据过期（详见 `05-项目问题总结.md`）。
- 技能包在不改动项目代码的前提下，通过只读网关镜像真实表结构，把“能否研究、数据时点、来源与限制”全部显式化，满足研究复核的可追溯要求。
- 实时行情、全市场个股日线、财报等当前缺失能力，均以明确限制呈现，不伪造。
