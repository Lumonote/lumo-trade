# 验证报告

> 验证脚本：`test/skills/verify.py`；机器结果：`test/docs/verification-results.json`。验证通过独立子进程驱动各技能 `run.py`，覆盖正常返回、历史日期、无数据、数据源失败四类场景。

## 1. 验证方法

- 对每个场景执行真实命令并解析 JSON 信封；
- 断言该场景的期望状态与数据；
- 对每个信封额外检查两条全局不变量：
  1. 必须包含合规声明（disclaimer）；
  2. `data_nature` 不得为 `live_quote`（历史快照不得被改标为实时）。

- **正常返回**：`market_breadth --date 2026-06-01` → `status=ok`，rows=5957，up=3823/down=1703/flat=431。
- **历史日期**：`daily_basic_snapshot --date 2026-01-05` / `index_daily --date 2026-07-15` → `data_nature=historical_snapshot`，`as_of` 为实际日期。
- **无数据**：

  - `financial_statements --code 600519` → `no_data`（空表）；

## 5. 安全确认

- 验证未读取任何密钥到日志；
- 未删除、未重置任何用户数据；
- 验证唯一写入的文件是 `test/docs/verification-results.json`；
- 所有数据库连接均以 `?mode=ro` 只读打开。

## 6. 已知限制（非缺陷）

- 验证结果依赖本地库当前内容；若本地库被更新，各表行数/日期会变化，但四类场景的**状态判定逻辑**应保持成立。
- 实时行情、全市场个股日线、财报等当前缺失能力不在本次验证范围，对应场景以 `no_data/error` 正确呈现。
