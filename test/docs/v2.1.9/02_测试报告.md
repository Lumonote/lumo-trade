## 3. 已证实缺陷详情

### D-001　市场快照对非 dict 元素崩溃（P3，本次新增）
- **代码位置**：`analysis/market_health.py:96`，`market_snapshot` 内 `r.get("trade")` 直接调用，缺少 `isinstance(r, dict)` 防御（对比 `normalize_bars` 有该防御）。
- **复现步骤/输入**：在隔离环境调用 `market_snapshot(x)`，输入分别为 `["x"]`、`[123]`、`[None]`、`[["nested"]]`。
- **预期**：跳过/清洗非 dict 元素，函数正常返回（或返回空快照）。
- **实际**：四类输入均抛 `AttributeError`（'str'/'int'/'NoneType'/'list' object has no attribute 'get'），整个快照函数崩溃。
- **影响等级**：P3。上层 worker 有 try/except 兜底并保留原快照，不损坏数据，但当轮更新失败。
- **证据**：`evidence/D-001_repro.txt`；反例测试 `tests/test_v219_regression_guards.py::test_d001_*`（xfail strict）。

### D-002　get_bars 缓存不足 limit 静默截断（P3，本次新增，当前生产路径不可触发）
- **代码位置**：`webui/services/kline_service.py:325-336`，`_cached_bars` 仅校验 `len(cached) >= max(21, min(limit,60))`，命中后返回 `cached[-limit:]`。
- **复现步骤/输入**：先写入 60 根磁盘缓存，再分别请求 `limit=250`、`limit=61`。
- **预期**：缓存不满足实际 limit 时视为未命中，重新 fetch 足量数据。
- **实际**：请求 250 仅返回 60 根、请求 61 仅返回 60 根，静默截断且不重新 fetch。
- **影响等级**：P3（潜在隐患）。条件选股固定 `KLINE_BARS=120` 且缓存写入也是 120 根，当前生产路径不触发；一旦出现更大 limit 或缓存被短窗口写入即触发。
- **证据**：`evidence/D-002_repro.txt`；反例测试 `...::test_d002_*`（xfail strict）。

### D-003　margin_metrics 文档与实现不一致（P4，代码正确）
- **代码位置**：`analysis/market_health_fusion.py:54` docstring。
- **内容**：docstring 称“融券余量跨标的单位混合，不累加”，但实现把 `rqye` 累加。经 TuShare 官方口径核实，`rqye` 是融券**余额（元）**（融券“余量”对应 `rqyl`，单位股），两所单位一致、可加，**代码正确**；docstring 混淆字段且错误描述口径。
- **影响等级**：P4（文档级）。`rqye` 仅在 `details.series` 展示，不参与任何压力计分，对计算零影响。
- **证据**：`evidence/D-003_rqye_doc_mismatch.txt`；正确行为测试 `...::test_d003_*`（passed）。
