## 3. 影响范围与兼容性分析

1. **向后兼容**：变更是增量式的。新增模块、路由、服务均为独立挂载；未发现对既有 API 路径、请求/响应字段或数据库既有表结构的破坏性修改。
2. **数据库兼容**：schema 版本化至 v21，全部迁移使用 `IF NOT EXISTS`/幂等写法，旧库可平滑升级；旧 `kronos_data.sqlite` 在首次解析时自动复制为 `lumo_data.sqlite`，legacy 保留（已实测，见测试报告）。
3. **依赖兼容**：未引入新的第三方强依赖，新功能复用既有 pandas/numpy/akshare/robyn。
4. **降级兼容**：网络不可用、TuShare 无 token、缓存损坏等场景均安全降级为 `None`/不可用标注，不补零、不冒充盘中数据。
5. **改动风险集中点**：`stock_screener_service.py` 与 `screener_cache_repo.py` 是唯一涉及既有用户高频路径（条件选股）的改动，已作为异常攻击与并发测试的重点。
