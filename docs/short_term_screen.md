# 短线作战大屏

全局右上角“短线大屏”按钮在原页面上打开独立全屏工作区。原生Fullscreen API作用于模态窗口内部的容器；浏览器未允许原生全屏时仍铺满应用窗口。“返回”移除大屏并保留原页面表单、滚动与状态。独立地址为`/desktop/short_term`。

## 观察内容

- 板块异动雷达、个股异动、实际涨跌停及连板、资金、盘口事件时间线。
- 中央底部展示大单买入监控，以及涨停、跌停、股票热度和人气快速攀升榜单；右侧为大笔卖出监控、信号矩阵和市场快讯。涨跌停按实际限价日统计并标注日期。人气榜显示“昨日排名→当前排名、上升N名”；默认筛选当前前100名、上升至少20名，按当前名次优先，可切换范围和名数门槛。缺少对比数据不推算上涨名次，股价涨幅不参与此榜。
- 四源消息按标题去重，保留多来源、完整日期与原文入口。主页消息统一进入市场快讯流，不再分割核心消息区域。已归档日历与消息分类仍可在相关明细和既有接口中读取，主页不再自动刷新日历。
- 中央透视图显示已取得的行业和事件日成分归属。板块与股票之间可互相点选，消息、会议、资金和原始异动均能穿透查看。
- 全量列表可搜索、分页、导出CSV。历史日只读已有归档，缺快照不使用当前数据冒充历史。

界面参照用户截图的近黑背景、冷灰细框、银灰卫星与设备、低饱和分色线束和蓝青信号矩阵。移除线框显示器、机柜、工作站底座与地面装饰，空出的区域展示三排可点选的关联股票。宽屏最多12个板块、24只股票；窄一些的桌面显示10个板块、18只股票，小屏按宽度降低容量，避免节点重叠。各板块轮流提供关联股，显示的股票均有对应归属连线。头部只保留一行检索、快照、自动监控状态、滚动/动效开关及全屏/返回。来源状态可从底部口径明细查看。不依赖生成图片。

3D场景使用本地vendored Three.js r180（MIT，许可证位于webui/static/vendor/three-r180/LICENSE），无需CDN。WebGL不可用时使用Canvas降级场景。

## 自动监控与动效

主页移除当日核心消息、未来催化日历和手动刷新按钮，替换为大单买入、大笔卖出监控。所有滚动列表默认自动往返滚动，悬停、键盘聚焦或打开明细时暂停，手动滚轮操作后暂停8秒，也可全局暂停。相同数据不重建列表，变化时保留滚动位置。

首屏只读完整快照，之后各分区错峰独立采集、发布和重试：盘口15秒、个股异动60秒、消息45秒、人气180秒、板块资金600秒、收盘涨跌停核验1800秒。已有缓存时首次检查也等到对应周期并加错峰偏移，不在打开页面时同时重新采集所有来源。`/api/short-term/feed?kind=radar|news|popularity|sectors|limits&after=版本`只在版本变化时返回对应分区；后台网络请求互不等待，发布阶段合并最新输入，防止覆盖其他来源。休市降低采集频率，隐藏页面暂停请求，历史快照只读，不反复轮询整屏任务。

所有列表使用浏览器原生的线性合成动画，固定18像素/秒，无JS逐帧滚动。尾部以仅展示的副本无缝接续，计数、检索和导出仍只使用真实记录；副本不进入键盘焦点和无障碍树，点击仍打开原始记录。悬停切回原生滚动，更新保留动画位置，尺寸只在内容或窗口变化时测量。增量复用未变化的行，不重建整列；取消行级入场闪烁。三维静态线条合并绘制，报价变化只改标签，不重建场景；固定标签只在布局变化时定位，保留光点、卫星和面板扫描。

分区数据到达时，只绘制该分区所属面板；消息更新不会连带重绘板块、个股、榜单和三维场景。关系图只在板块更新或用户筛选时检查结构，报价变化不触发结构重建。新记录插到顶部时保留原可见行的像素位置。

真实新增或变化的记录会触发一次4.8秒极光：柔和聚亮，再缓缓散去；只合成透明度和位移，不移动文字或改变行高。首屏缓存、搜索和筛选不触发；离屏新行等待可见后才亮起。全屏同时最多8个发光元素，包含分区标题、行和节点，结束即清理。

连线使用亮白光头与冰蓝、淡紫渐隐长尾，像陨石沿既有关系线滑落。默认将曲线投影、按屏幕距离等距采样，由浏览器合成层执行仅含transform/opacity的匀速动画，不依赖页面JavaScript回调频率。常态流星与真实更新各走独立轨道，新数据不会重置正在滑落的光头，首尾柔和淡入淡出。更新按雷达→板块→股票的视觉时序抵达并点亮节点。WebGL保留GPU纹理插值兼容路径；无WebGL时缓存底图与曲线，仍使用相同合成层动画。标签只在布局或选择变化时定位。离屏、隐藏页面或关闭动效均暂停。此动效表示数据到达，不表示实际资金流动。

原8板块布局合批后，同一真实快照的每次场景绘制调用247→54次；扩容到12个板块、24只股票后为74次。内嵌浏览器中曾实测JavaScript回调约30帧而每帧绘制不足1毫秒，因此流星改由合成层持续移动。验收检查正常光束独立运行、新数据不替换常态动画、关键帧仅含transform/opacity、关闭动效和离屏暂停、重建不泄漏纹理。1440和390宽度、Canvas兼容模式同时检查节点边界、间距和点选。

板块报价优先使用同代码、带当日源时刻的实时值，收盘原值与日期独立保留。雷达行业与资金接口分类无法对应时，不强行改名匹配：用同日已覆盖成分股的等权涨跌幅和主力净流入合计，明确标注“成分均涨 / 成分净额”、有效覆盖数和日期。空值不补零，旧日成分不混入新日汇总。雷达、全部板块表、详情及CSV使用一致的展示口径，原收盘值仍保留。

买卖通道每次取源最新200条，按事件ID累计去重，单侧最多保留2000条已采集记录，跨日分别归档；某侧失败独立保留其原日期与抓取时间。源只有时分秒，使用腾讯指数报价交易日校验；金额、价格、数量仅在源四字段通过数量×价格一致性校验时展示，否则留空。这是盘口异动监控，不等同于完整逐笔委托清单。

设备轻微悬浮、真实归属连线上流动光点、面板扫光、矩阵呼吸与新记录高亮共同构成持续运行状态。数据数值只随来源更新；动效开关可以暂停视觉动效。场景复用点缓冲区，以20fps为上限，数据未变化时不重建3D内容。

## 接口

- `GET /api/short-term/overview?date=YYYY-MM-DD`：聚合只读数据，省略日期查看最新。
- `GET /api/short-term/section?kind=sectors|stocks|news|core_news|short_news|calendar|limits|limit_up|limit_down|hot_stocks|popularity_rises&q=...&date=...`：完整分区查询。
- `GET /api/short-term/detail?kind=sector|stock|news|event|order&id=...&date=...`：完整对象及关联记录。
- `POST /api/short-term/refresh`：启动去重后台任务，逐来源报告状态，失败保留原数据与时点。
- `GET /api/short-term/orders?date=YYYY-MM-DD`：大笔买卖监控，当前视图自动后台更新，历史日只读归档；`big_buys` / `big_sells` 同样可通过分区接口检索。

缓存复用SQLite `kv_cache`的`short_term_screen`命名空间，保存输入、更新时间、后台任务与每日聚合快照，无新增数据库迁移。所有来源独立保留实际日期，刷新时间不替代行情或消息发表时间。关联规则是名称/代码/题材关键词匹配，不推断因果或实际交易者。

财经日历使用TuShare `eco_cal`。源接口可能忽略offset，改用国家×周窗口，并在达到100条上限时继续按日拆分；重复原始记录去重。会议基线包含主办方原文、核验日、时区与验证点，不能把媒体提取结果升级为官方确认。未明确时区的数据不猜测北京时间。
